# wxpusher-integration v1.0.5

为脚本、后端服务、定时任务和 CI 接入或排查 WxPusher 通知的 Agent Skill。
覆盖标准推送、UID/Topic、SPT、响应判断、凭据配置和故障处理，主要使用简体中文。

## 本次变化

- SPT 默认使用 `POST https://wxpusher.zjiecode.com/api/send/message/simple-push`，
  请求类型为 `application/json`；单人使用已有 `spt`、`content`、`contentType`，
  无需改用 appToken 或 UID。
- 正文保留 `/context`、`https://...`、中文、换行及百分号等原文，经过 JSON
  序列化后以 UTF-8 发送，不做 URL 百分号编码。
- GET 保留为受限便捷接口。正文含 `/`、编码后出现 `%2F` 时，当前使用 SPT POST；
  不通过双重编码、替换正文字符或重复请求规避限制。
- 公开官方文档、用户提供的此前实测摘要及转述的官方人工答复分别记录。
  编码斜杠限制来自后两类证据，公开文档尚未明示该限制，也未宣称整个 GET 发送停用。
- 按本次重新核验的公开资料修正旧发送状态查询停用说明，停止查询和轮询，
  不把停用提示当作发送失败而自动重发。

既有用户长期授权、逐目标业务码检查、有限重试和密钥保护语义继续保留。
HTTP 200 但业务失败不能报告发送成功；接口接受任务不代表用户已收到或阅读。
2026-11-12 重新核验的范围为 SPT 请求、发送响应和旧查询停用说明，其余 API/SDK
保留原核验日期。来源和行为验证见 [1.0.5 维护记录](https://github.com/hunxuankai/wxpusher-integration/blob/634107ef4e5c27ad817356c6c1bc1c599f86f075/docs/reviews/2026-11-12-v1.0.5.md)。

## 安装与运行前提

下载附件 `wxpusher-integration-1.0.5.zip`，解压后将完整的
`wxpusher-integration` 文件夹复制到宿主支持的 skills 目录。Codex 用户级目录为
`~/.agents/skills/`；已有同名目录时先备份，再安装完整的新版本。

也可从 GitHub 当前安装源安装：

```sh
npx skills add hunxuankai/wxpusher-integration --skill wxpusher-integration
```

Skill 本体只有 Markdown/YAML，没有 Python、Node.js 或 PowerShell 运行时依赖。
执行集成时使用宿主已有的文件、HTTP 和开发工具；真实推送需要使用者自己的
WxPusher 配置，并遵循已授权的用途、对象和频率。微信 ClawBot 仍需绑定、启用和
激活；该渠道当前只支持文本通知且不支持上行，不能向任意好友或微信群寻址。
