## 修改前基线

独立检索代理先不读取 skill，回答六项实际问题，再读取原 1.0.3 重答。
无参考阶段的微信答案为：“据既有知识 WxPusher 通常通过微信关注其公众号并取得 UID
接收应用消息；当前渠道、前提和限额不能确认，不认为支持任意好友/群。”
读取原版后能找到 ClawBot 的 24 小时/10 条限制，但仍无法集中获得绑定、启用和渠道能力说明。

原版触发描述被指出：“SKILL.md:18 字面将独立 UID/Topic 作为充分触发条件，
与 description 的 WxPusher API 语境不一致”。代理基于业务判断未实际误选 Kafka，
因此记录为文本歧义，不宣称已经复现运行时误触发。

另外四项（缺凭据继续开发、逐目标失败、SPT 撤销不确定性、长期授权与 GET 编码）
读取原版后均有明确依据，修改时保留其语义。此次修正针对渠道信息缺口和触发歧义，
未添加与检索失败无关的通用纪律规则。

## 修改后检索验证

独立代理重读 1.0.4，完成以下 13 项应用/检索场景；维护者核对实际答案与源码，均符合预期。
另人工复核“仅说微信通知且未选择服务商”应不自动选择 WxPusher。

| 场景 | 实际结论 |
| --- | --- |
| 微信支持与前提 | ClawBot 文本通知；App 绑定/启用、微信侧激活；不推断任意好友/群能力，不断言公众号全部停用。 |
| 通用 UID / Kafka Topic | 不单独触发 skill。 |
| Python 任务无凭据 | 用命名变量和占位继续开发与模拟验证；SPT 缺失同样处理。 |
| 顶层 1000、单目标失败 | 失败或部分失败；不宣称全部接受或用户收到。 |
| SPT 泄漏后重新扫码 | 不能保证旧值失效；公开资料未提供已核实撤销流程。 |
| 长期授权与 GET 编码 | 范围内不重复确认；SPT/正文逐路径段 UTF-8 百分号编码一次。 |
| App 有消息但微信没有 | 检查 ClawBot 绑定、启用、激活时效、10 条限额；不反复重发。 |
| 回复 ClawBot 触发上行 | 官方当前不支持，不能承诺 `send_up_cmd` 回调。 |
| Topic/SPT 绕过微信限额 | 不能从 API 模式推断绕过独立渠道限额。 |
| 30000 个普通汉字 | 约 90000 UTF-8 字节超限；需缩短/分段且检查转换后 HTML。 |
| 标准 GET 多 UID/Topic | 不支持，改用标准 POST 并遵守数量限制。 |
| 指定企业微信/Telegram | 遵循所选渠道，不自动替换为 WxPusher。 |
| 上文已选 WxPusher、本轮只说加通知 | 保留上下文选择，使用该 skill。 |
